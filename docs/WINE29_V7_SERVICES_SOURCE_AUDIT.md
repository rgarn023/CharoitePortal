# Wine29 v6 postmortem — confirmed missing services.exe builtin mapping

**Date:** November 7, 2026. **Source:** Owner's v0.84 READ-ONLY PID 0034/PE+wineserver audit. **Scope:** Existing v6 scratch *not accessed* by CI. No Android/device execution.

Wineboot 0024 and its automatic child 002c both independently mapped PE/NTDLL/kernel32/API-set and exited zero. PID 002c then requested `C:\\windows\\system32\\services.exe` at PE line 836. In a separate process context 0034, the loader searched services.exe (PE lines 843–844), found no C: file, then reported `cannot find builtin library` for services.exe (PE line 846), followed by exit `0xC0000135` (line 848). A second attempt is seen at PE line 2507. This strongly identifies missing **services.exe** in the v6 PE cohort as the immediate loader failure (not a proven unnamed DLL). v0.84 server log 410,477 bytes, 4,360 lines; no fatal/err markers; whole-file 512 KiB cap accepted. No supported games or complete prefix.

The previous sealed dataset is exactly 34 DLLs + ARM64 wineboot.exe + 76 NLS; **no services.exe**. Wine's pinned `programs/services/Makefile.in` declares `MODULE = services.exe` and ordinary dependencies `rpcrt4 advapi32 userenv setupapi`. We will **not** borrow a Windows proprietary executable or install a random external services.exe.
